## 1. Executive Summary

Phases 1 through 11 transformed SHIVANI from an instruction-following assistant into a goal-directed autonomous computer-use agent equipped with vision understanding, proactive memory, multi-agent orchestration, and dynamic self-correcting planning.

However, SHIVANI currently lacks a **connected knowledge environment** representing the user's digital workspace. Currently:
1. **Isolated Information Silos**: Project files, PRDs, research summaries, git commits, personal notes, and code repositories exist as disconnected files on disk. The agent must read raw files on-demand without cross-document relationships.
2. **Naive File Scanning vs. Semantic Retrieval**: When asked questions about architecture or business logic, previous approaches rely on grep/regex searches or full-file reads that quickly exhaust LLM context windows and lose structural context (headings, tables, call hierarchies).
3. **Absence of Provenance & Exact Citations**: Answers generated by agents lack verified, line-accurate provenance pointing back to the specific source document, section, and line numbers.
4. **Knowledge Drift & Silent Contradictions**: As projects evolve, outdated specifications (e.g. an old design doc stating MongoDB vs. a new PRD specifying PostgreSQL) lead to conflicting information without resolution mechanisms.
5. **Secret Exposure Risk**: Naive indexing of codebases and workspace directories risks ingesting API keys, `.env` credentials, private SSH keys, and connection strings into search indices and LLM prompts.

Phase 12 implements the **SHIVANI Knowledge OS**: a local-first, permission-aware, secret-safe, and unified knowledge architecture that integrates:
- **Unified Knowledge Model**: Typed knowledge items (`DOCUMENT`, `CODE_FILE`, `PROJECT`, `RESEARCH_SOURCE`, `DECISION`, `REQUIREMENT`, `PERSONAL_NOTE`, `TASK`, `ARTIFACT`, `ENTITY`).
- **Multi-Format Ingestion**: Structure-preserving parsers for Markdown, Code, Plaintext, JSON/YAML, CSV/TSV, and Presentations.
- **Structure-Aware Chunking**: Preserves section heading breadcrumbs, code blocks, and markdown tables.
- **Code Intelligence & AST Symbol Graph**: AST-level symbol extraction (classes, functions, methods, imports, calls, signatures, docstrings).
- **Project Discovery & Intelligence**: Auto-detection of project roots, tech stacks, dependencies, and architectural blueprints.
- **Hybrid Retrieval & Reranking**: BM25 keyword matching + Vector semantic search + Metadata filtering + Graph structural boost + Cross-evaluative reranking.
- **Knowledge Graph**: Directed multigraph tracking dependencies, implementations, technologies, decisions, and documentation links.
- **Exact Provenance & Citations**: Line-accurate source attribution for every retrieved insight and synthesized response.
- **Knowledge Conflict Detection**: Real-time detection and resolution of contradictory facts across disparate documents.
- **Zero-Secret Indexing**: Pre-indexing regex and entropy scanner that redacts credentials before storage or embedding.

## 2. Current State Assessment

### 2.1 Existing Memory Subsystem (`memory/`)
- **Status**: Provides scoped SQLite memory (Global, User, Project, Session) across Working, Episodic, and Semantic categories.
- **Gaps**:
  - `memory/semantic/manager.py` only stores key-value pairs (`store_fact(key, value)`). It does not chunk large documents, index code ASTs, or compute dense vector embeddings.
  - Does not support hybrid search combining BM25 and vector similarity.
  - Does not provide citation graphs or provenance tracking to line numbers.
- **Integration Strategy**: `KnowledgeOS` will serve as the heavy-duty indexing, document comprehension, and workspace intelligence engine, while `MemoryManager` handles high-level user preferences and episodic dialogue history.

### 2.2 Existing Coding Agent (`agents/coding/`)
- **Status**: Implements `ProjectDetector`, `CodeAnalyzer`, `CodeSearch`, `GitManager`, `PatchManager`, and `TestRunner`.
- **Gaps**:
  - `CodeSearch` uses basic keyword searching or simple regex across file lines.
  - Does not maintain a persistent AST symbol index of classes, methods, imports, and caller/callee relationships.
  - Lacks understanding of high-level architectural decisions and requirements stored in project documentation.
- **Integration Strategy**: `CodingAgent` will query `KnowledgeOS.get_project_context()` and `KnowledgeOS.search_symbols()` during its `UNDERSTAND` and `PLAN` stages.

### 2.3 Existing Research Agent (`agents/research/`)
- **Status**: Gathers web and academic sources, categorizes authority tiers, detects contradictory claims, and saves markdown bundles to `ArtifactManager`.
- **Gaps**:
  - Research bundles are stored as static artifacts; their structured insights are not indexed into a unified workspace knowledge graph.
- **Integration Strategy**: Research results will be automatically ingested into `KnowledgeOS` as `RESEARCH_SOURCE` items with source URLs, authority tiers, and cross-references.

### 2.4 Existing Presentation Agent (`agents/presentation/`)
- **Status**: Generates slides from research bundles or input markdown.
- **Gaps**:
  - Requires explicit input text; cannot autonomously query project metrics, architectural decisions, and accomplishments from the workspace.
- **Integration Strategy**: `PresentationAgent` can pull structured facts and citations directly from `KnowledgeOS` when generating project briefs and sprint demos.

## 4. Key Architectural Decisions

1. **Local-First, Zero External Vector DB Dependency**:
   - Rather than requiring heavy external daemons (Chroma, Qdrant, Pinecone, or Milvus), storage is backed by SQLite with optimized indexes and optional FTS5.
   - Embeddings use a deterministic local provider with cosine similarity fallback and pluggable adapters for cloud models (Gemini/OpenAI) and local servers (Ollama).
2. **Secret-Safe Pre-Indexing**:
   - Every file ingested is scanned by `SecretScanner` prior to chunking or storage.
   - Detected keys (e.g. `sk-proj-...`, `ghp_...`, `AKIA...`, private keys, passwords) are automatically sanitized to `[REDACTED_API_KEY]`.
3. **Exact Line Provenance**:
   - Chunks retain original start and end line numbers and hierarchical heading paths (`["README.md", "Architecture", "Storage Engine"]`).
   - Every citation generated includes exact file path, section, and line bounds.
4. **Knowledge Conflict Detection**:
   - Compares opposing factual assertions across documents and maintains a conflict registry, preventing outdated specifications from corrupting code generation.
