## 1. Executive Summary

Phase 11 shifts SHIVANI from an instruction-following task execution engine into a **high-order, goal-directed, self-correcting agentic intelligence**. 

While Phases 1 through 10 provided foundational execution primitives (OS controls, browser automation, multi-agent tools, memory, security vaults, and spatial vision understanding), planning was previously limited to:
1. Single-pass linear step lists generated by LLM prompting without formal validation.
2. Hardcoded keyword heuristics for basic DAG decomposition across specialized agents.
3. Brittle error recovery: failed steps often led directly to task failure without dynamic replanning or root-cause evaluation.
4. Rigid command semantics unable to disambiguate vague intents from missing critical parameters without either guessing or stalling.

Phase 11 establishes a dedicated, industrial-grade `planning/` subsystem that decouples goal comprehension, multi-level decomposition, dependency graph analysis, constraint enforcement, priority scheduling, dynamic self-correction replanning, and state serialization.

## 2. Current State Assessment

### 2.1 Current Planner (`core/planner/planner.py` & `core/orchestrator/planner.py`)
- **Status**: Implements basic `TaskPlanner` delegating to `LLMProvider.generate_plan()`.
- **Deficiencies**:
  - Plan output is a flat list of `PlanStep` items (`tool`, `action`, `arguments`, `expected_outcome`).
  - No dependency modeling: all steps are treated as sequential, preventing parallel execution of independent sub-goals.
  - No constraint verification: ignores deadlines, resource contention, and device availability until execution time.
  - Duplication: separate planner implementations existed in `core/planner/` and `core/orchestrator/`.

### 2.2 Current Orchestrator (`core/orchestrator/orchestrator.py`)
- **Status**: Coordinates task pipelines (`_run_task_pipeline`), executes multi-agent DAGs (`submit_multi_agent_goal`), handles permissions, emergency stops, and audit events.
- **Deficiencies**:
  - `submit_multi_agent_goal` polls `ready = dag.get_ready_subtasks()` with fixed `asyncio.sleep(0.05)` loops.
  - Subtask execution simply submits subtask titles back to `self.submit_task()`, re-running isolated planning loops rather than coordinating within a unified goal context.
  - Lacks dynamic replanning when a subtask fails: a single subtask failure immediately sets `dag.mark_failed()`.

### 2.3 Agent Registry (`core/agents/registry.py`)
- **Status**: Tracks 7 specialized sub-agents (`computer_agent`, `browser_agent`, `coding_agent`, `research_agent`, `presentation_agent`, `documentation_agent`, `phone_agent`) with capabilities, keywords, and risk tiers.
- **Deficiencies**:
  - Matcher uses simple keyword containment scoring (`sum(1 for kw in desc.keywords if kw in query_lower)`).
  - Cannot evaluate composite capabilities (e.g. tasks requiring both `browser` and `research` or `computer` and `coding`).

### 2.4 Task State Management (`core/tasks/task.py`)
- **Status**: Pydantic models for `Task`, `TaskStatus`, `TaskPriority`, `PlanStep`, `TaskPlan`.
- **Deficiencies**:
  - `TaskPlan` lacks graph structure (nodes, directed edges, parallel branches).
  - No explicit tracking of intermediate outputs or artifacts passed between steps (data pipelines).

### 2.5 Memory Integration (`memory/manager.py`)
- **Status**: Scoped SQLite memory (working, episodic, semantic, user preferences).
- **Synergy Opportunity**: Goal parser and planner must actively query user preferences (`MemoryManager.preferences`) to automatically resolve underspecified constraints (e.g., preferred browser, coding conventions, output directories).

### 2.6 Vision Integration (`vision/service.py`)
- **Status**: Complete Phase 10 visual intelligence (high-DPI capture, OCR, UI tree, grounding, diffing, privacy redaction).
- **Synergy Opportunity**: Computer-use reasoning in Phase 11 can use visual verification feedback to inform the `Replanner` when a GUI action fails or produces unexpected screen state.

### 2.7 Recovery Integration (`recovery/checkpoint_manager.py`, `recovery/rollback_manager.py`)
- **Status**: Checkpoints task state to disk and provides 1-click rollback snapshots.
- **Synergy Opportunity**: Phase 11 `TaskGraph` must serialize execution state to disk so long-running multi-agent workflows can be resumed or rolled back at any node.

## 3. Known Limitations & Gaps Identified

1. **Lack of Goal Disambiguation**: The assistant either blindly executed underspecified commands with defaults or relied on human prompts for basic parameters.
2. **Linear Execution Bottleneck**: Independent tasks (e.g., research on Source A and Source B, or generating slides while drafting social copy) ran sequentially instead of concurrently.
3. **Absence of Self-Correction / Replanning**: When a step failed (e.g., website blocked, button not found, command syntax error), the system failed the task rather than synthesizing an alternate plan (e.g., trying a different search engine, using UI accessibility fallback, fixing command arguments).
4. **Data Isolation between Subtasks**: Outputs from earlier subtasks (e.g., research summary markdown) had to be manually transferred rather than flowed as typed inputs to subsequent subtasks (e.g., report builder).

## 4. Architecture Changes Required for Phase 11

### 4.1 Dedicated Planning Subsystem (`planning/`)
We introduce a clean, decoupled `planning/` package:

```text
planning/
├── __init__.py               # Public exports
├── models.py                 # Structured Goal, SubTaskPlan, TaskNode, PlanEdge models
├── goal_parser.py            # Converts NL into structured Goal + Clarification detection
├── task_decomposer.py        # Hierarchical goal decomposition into SubTaskPlans
├── dependency_graph.py       # DAG TaskGraph with cycle detection & topological sorting
├── priority_engine.py        # Dynamic priority assessment (bottlenecks, deadlines, urgency)
├── strategy_selector.py      # Selects execution strategy (Sequential, Parallel, Hierarchical)
├── constraint_engine.py      # Enforces permissions, resource limits, and time bounds
├── plan_validator.py         # Validates DAG integrity, agent capability match, parameter validity
├── replanner.py              # Self-correction: analyzes failures, diagnoses causes, synthesizes new paths
├── plan_serializer.py        # Serializes TaskGraph to/from JSON/YAML with checkpoint state
└── planner.py                # AdvancedPlanner facade orchestrating the complete pipeline
```

## 5. Verification Strategy

1. **Goal Parsing Tests (`tests/planning/test_goal_parser.py`)**:
   - Structured extraction of objective, constraints, outputs, deadlines.
   - Ambiguity detection: asks clarification when essential parameters (e.g., recipient) are missing; executes when context is sufficient.
2. **Task Decomposition Tests (`tests/planning/test_task_decomposer.py`)**:
   - Multi-agent goal decomposition into typed subtasks with dependencies and assigned agents.
3. **Dependency Graph & DAG Tests (`tests/planning/test_dependency_graph.py`)**:
   - Cycle detection (detects and rejects invalid cycles).
   - Topological sort and parallel layer batching.
4. **Strategy & Constraint Tests (`tests/planning/test_strategy_and_constraints.py`)**:
   - Strategy selection across diverse goal profiles.
   - Constraint checks for permissions, concurrency, and time budgets.
5. **Priority Engine Tests (`tests/planning/test_priority_engine.py`)**:
   - Dependency bottleneck identification and priority assignment.
6. **Plan Validation & Serialization Tests (`tests/planning/test_plan_validator.py`)**:
   - Structural and capability validation.
   - JSON serialization, deserialization, and state restoration.
7. **Replanner & Self-Correction Tests (`tests/planning/test_replanner.py`)**:
   - Failure diagnosis and dynamic DAG modification (inserting fallback node, switching tool, adapting arguments).
8. **End-to-End Orchestrator Integration Tests (`tests/planning/test_planning_integration.py`)**:
   - Full autonomous multi-step workflow execution with parallel batches and intermediate data piping.
9. **Full Regression Test Suite**:
   - Verify all 192 existing tests remain 100% passing.
