# SHIVANI — Long-Running Checkpointed Workflows & Artifact Management

## Overview
Complex professional tasks (e.g. building an MVP, conducting deep research, or generating a complete hackathon package) require long-running, multi-stage workflows that span multiple agents.

SHIVANI supports **Stateful Stage Checkpointing** and **Centralized Artifact Organization** to ensure resilience against crashes and seamless pausing/resumption.

---

## Persistent Workflow States
- `PENDING`: Initial registration.
- `RUNNING`: Actively executing workflow steps.
- `WAITING_FOR_APPROVAL`: Paused awaiting human authorization on `CRITICAL` or sensitive steps.
- `PAUSED`: User-initiated pause.
- `FAILED`: Execution halted with captured failure diagnostics.
- `CANCELLED`: Aborted by user or Emergency Stop.
- `COMPLETED`: All stages successfully finished and verified.

---

## Stage Checkpoints

Workflows can associate steps with explicit stages:
1. `research`
2. `requirements`
3. `architecture`
4. `implementation`
5. `testing`
6. `documentation`
7. `presentation`
8. `report`

### Checkpoint Storage Contract
Whenever a stage completes, a checkpoint record is saved to:
`workspace/shivani-artifacts/checkpoints/<workflow_id>_<stage>.json`

Each checkpoint records:
```json
{
  "checkpoint_id": "wf-12345",
  "stage": "research",
  "timestamp": "2026-09-24T04:30:00Z",
  "data": {
    "stage": "research",
    "step_index": 0,
    "context_data": {
      "sources": [...],
      "research_summary": "..."
    }
  }
}
```

### Crash Recovery & Resumption
If execution is interrupted:
```python
result = await orchestrator.resume_workflow_from_checkpoint(workflow_id, stage="architecture")
```
The Workflow Engine restores `context_data`, sets the execution pointer past the checkpointed step, and continues without re-executing earlier stages.

## Centralized Artifact Management (`ArtifactManager`)
All files generated by SHIVANI are saved in `workspace/shivani-artifacts/` to avoid polluting the user's root directories:

```
workspace/shivani-artifacts/
├── project/          # Generated MVP code, scaffolding, and source files
├── research/         # Cited research reports, sources.json, summary.json
├── presentations/    # Generated PowerPoint decks (.pptx), pitch bundles, Q&A
├── reports/          # README files, API specs, architecture ADRs
├── checkpoints/      # Persistent JSON state checkpoints
└── logs/             # Execution and diagnostic logs
```
